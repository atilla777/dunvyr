# Знания и SDLC

## Разделение источников

- `AGENTS.md` — короткая навигация и базовые абсолютные запреты.
- `docs/index.md` — OKF Bundle 0.2, точка входа.
- `docs/product/` — **принятые авторские требования/ограничения**; агент не переписывает их автоматически под код.
- `docs/rules/` — **обязательные инженерные соглашения**.
- Native Beads Epic/Task/Bug — детали принятого при планировании, acceptance criteria, владельцы задач и dependencies (`blocks`), без второго трекера.
- `docs/spec/` — **проверенные фактически реализованные** поведенческие контракты по функциональным понятиям, обновляются при `mis-run`.

При столкновении product vs technical implementation приоритет имеют явные продуктовые ограничения; если они несовместимы, остановить спорное изменение и получить содержательное решение. Нет обязательной предварительной spec на каждый Epic/Task и отдельного tech-plan.

## Планирование

`/mis-plan` от реального состояния проекта и требований формирует ближайшие достижимые **проверяемые результаты**, не детализируя дальние технические микрошаги. Отдельная техническая Task допустима при реальной предпосылке (например, scaffold), но продуктовые Task по умолчанию — вертикальный срез через нужные контексты. При новой Task установить контексты-владельцы, public API потребителей, тесты, условия демонстрации и исключения. Не делить каждый слой на отдельную Task без причины.

## Реализация

`/mis-run` — native worktree, проверки по риску, независимый read-only review, документы/spec при необходимости. Только необходимые контексту файлы; не создавать лишние слои абстракций и не выносить всё в shared. Результат должен быть проверяем с пользовательской точки зрения, а не только по зелёному lint.

## Лицензии

Dunvyr Rules — адаптация, вдохновлённая Fate Condensed. Использование текста/отдельных лицензируемых игровых элементов в опубликованном продукте требует **проверки актуальной лицензии источника и выполнения атрибуции/уведомления об изменениях**; не копировать защищённые материалы без оснований. Хранить исходники/ссылки по необходимости; отдельный `LICENSE-THIRD-PARTY` создаётся при фактическом использовании контента. Иллюстрации и другие assets должны иметь подтверждённые права на использование.

## Операционные полномочия

MIS — установленный внешний пакет. Проверять его фактическую ревизию и контракт. Публикация в `main` выполняется только установленным протоколом MIS (`mis-proj-op-publish-change`): полный gate на интегрированном снимке, независимый review, non-force push, read-back. Закрытие Task означает подтверждённую публикацию, а не продуктовую приёмку; приёмка остаётся за владельцем. Режим прямой публикации принят владельцем 2026-11-05; см. [development-workflow](development-workflow.md).

## Отчёт

После задачи показывать: результат, как проверить, запущенные тесты/ограничения, какие contexts/контракты/spec изменены, Beads ID, Git/CI состояние (remote ref, SHA, read-back) и какая следующая команда MIS оправдана. Не выдавать отсутствие full E2E или неподтверждённую публикацию за полностью принятое изменение.
