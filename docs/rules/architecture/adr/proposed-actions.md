# Приватные подготовленные предложения действий

`gameplay` владеет коллекцией и ревизией предложений отдельно для каждой пары
«кампания — гость», а также собственными квитанциями идемпотентности. Коллекция
ограничена 20 ожидающими предложениями; совпадающие намерения разрешены.
Предложение не исполняет действие и не меняет очередь, сюжет или ресурсы.

Создание допустимо при активной встрече до очереди или вне своего хода, если
персонаж принадлежит гостю и выбор есть в публичном каталоге `adventures`.
Изменение и отмена требуют собственного текущего хода и присутствия; отмена
не требует, чтобы сохранённый выбор оставался доступным. Доступность в каталоге
отражает только известные ему исходные факты и не гарантирует последующего
исполнения. Для недоступного выбора проекция не раскрывает его идентификаторы
или названия; заново проверяются только данные из публичного каталога.

Команда удерживает write lock владельца жизненного цикла кампании до проверки
состояния, CAS коллекции и записи квитанции в одной транзакции. Для своего
хода guard присутствия удерживается до commit в порядке DB → presence. Повтор
идентичной команды после проверки членства возвращает исходную квитанцию даже
после изменения жизненного цикла; другой payload с тем же ключом конфликтует.
Изолированная квитанция не делится с командами очереди.

Публичный чат-поток и его история не содержат приватные предложения. После
commit порт `communication.public` адресует всем соединениям владельца только
кадр `{"type":"proposals_changed","campaign_id":"..."}` без содержимого и общей
последовательности. Перед отправкой каждому соединению повторно проверяются
сессия и членство. Это best-effort инвалидирование, не сохраняемый факт: при
ошибке доставки состояние не откатывается, после reconnect клиент получает
приватный REST snapshot и учитывает его версию.
