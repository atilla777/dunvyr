# Проверенные спецификации (`docs/spec/`)

Пока здесь только точка входа. Конкретные документы появляются/обновляются **при `mis-run` после реализации и проверки устойчивого поведения**, по предметным концепциям (например, `gameplay/turn-order.md`), а не по ID каждой задачи.

Не выводить нормативные требования исключительно из случайно существующего кода. Официальные продуктовые намерения — в `docs/product/`, инженерные ограничения — в `docs/rules/`, конкретика задачи — в Beads.
