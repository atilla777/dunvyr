# DDD без лишней обвязки

## Суть

Доменная модель содержит правила и инварианты, а не представляет собой анемичный CRUD поверх таблиц. Но не каждую запись нужно делать богатым Aggregate. Начинать с понятий, реально имеющих правила: Character, Encounter, TurnOrder, ScenarioState, Invitation, GameSession.

- **Entity** — объект с устойчивой идентичностью и контролируемыми переходами состояния.
- **Value Object** — immutable значение/правило без собственной идентичности (HP, SkillRating, DiceRoll, etc. если это оправдано).
- **Aggregate** — согласованная транзакционная граница с локальными инвариантами; не объединять всю Campaign со всеми персонажами/событиями в один гигантский агрегат.
- **Domain Service** — самостоятельное правило, не принадлежащее явно одной Entity.
- **Application Use Case** — работа с правами, транзакциями, вызовами другого context и портами.
- **Infrastructure Adapter** — SQLAlchemy/Pydantic/LLM/HTTP реализация и перевод представлений.

## Публичные контракты

Обмен между контекстами: IDs, immutable DTO/снимки, типизированные команды/результаты, ошибки предметной области; публичные DTO не должны экспортировать ORM model, SQLAlchemy Session или mutable Entity другого context. В Python допускаются `Protocol` и `dataclass`, не создавать интерфейс только ради интерфейса при отсутствии границы/тестовой подмены.

Domain exceptions — понятные нарушения правил; presentation отображает их в HTTP/WS ошибки. Не использовать `dict[str, Any]` как универсальный невалидируемый контракт для критических команд.

## Детерминированность и случайность

Итог проверки/боя при фиксированных входных данных и зафиксированном броске должен быть воспроизводим. Генератор кубиков — отдельная инъекция/порт, которую можно seed/mock в тестах; не генерировать случайность внутри AI narrator. Серверный генератор случайного выбора при ничьей тоже логируется.

Проверки статусов персонажа, доступа к информации и допустимости хода выполняются **на сервере**. UI — отображение прав, не security boundary.

## Соглашения имен и слоёв

Типовые пакеты организованы по контекстам. `public/` — минимальный набор для реальных потребителей. Не создавать универсальный RepositoryBase, ServiceBase, EventBus framework и сотни DTO без надобности. Объём слоя соответствует реальной бизнес-логике.

## Тестирование

Все доменные инварианты — через TDD с unit-тестами. Отдельные контрактные/integration тесты подтверждают, что публичные операции работают с настоящим persistence adapter. Условия ACL, concurrency, duplicate command/idempotency, hidden information и Fail Forward — обязательные риск-сценарии.
