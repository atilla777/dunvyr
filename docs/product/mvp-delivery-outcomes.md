# Предлагаемые вехи до MVP

Это **ориентиры результатов**, а не созданные Epic/Task. Точную декомпозицию, зависимости и Beads-статусы должен определить `/mis-plan` после проверки реального состояния репозитория и готовности MIS. Дальние технические детали не расписывать заранее.

| Ориентир | Демонстрация результата |
| --- | --- |
| Проект можно запускать и проверять | Локально поднимаются FastAPI и React; работает тестовая SQLite, unit/lint/architecture gates, доступна страница с телефона по LAN |
| Два гостя входят в одну кампанию | Создатель делится ссылкой, второй присоединяется, чат синхронизируется через WebSocket, права подтверждаются сервером |
| Кампания знает сценарий и персонажей | Загружаются локальные авторские файлы, игрок выбирает архетип, отображается сцена и доступная часть карты |
| Один сюжетный выбор разрешается полностью | Игрок предлагает действие, подтверждает в свой ход, сервер делает проверку, применяет outcome, сохраняет состояние, AI описывает результат |
| Сценарное взаимодействие живое | NPC отвечает по знаниям; открываемый/скрытый способ работает, Fail Forward, журнал обновляется по событиям |
| Бой и развитие работают | Общая очередь с противниками, HP, защита, урон, состояния, XP и улучшение навыка; без реального AI в тестах |
| Группа завершает приключение | Голосование за переход, мобильный UX, reconnect, продолжение сессии и достижение нескольких финалов в первом киберпанк-сценарии |
| MVP принят | Критерии из [mvp-acceptance](mvp-acceptance.md), CI и пользовательский прогон на нескольких устройствах выполнены; код интегрирован через workflow MIS и проверен/принят владельцем |

Каждый продуктовый вертикальный срез должен затрагивать только действительно нужные Bounded Contexts и иметь проверяемый эффект, а не просто добавлять пустые слои. Технические предпосылки вроде скелета приложения допустимы как самостоятельные вехи, если доказан их результат.
