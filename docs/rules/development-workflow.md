# Процесс разработки Dunvyr

## Источник инструментария

**MIS (Minimal Implementation Skills)** — внешняя система SDLC из https://github.com/atilla777/mis. Использовать установленную проверенную версию и её операции `/mis-install`, `/mis-plan`, `/mis-run`, `/mis-bug`, `/mis-status`, `/mis-update`; не создавать конкурирующий workflow/tracker, не изменять чужой upstream MIS автоматически.

Потребитель MIS: один Git-репозиторий, `AGENTS.md`, `docs/product/`, `docs/rules/`, `docs/spec/`, OpenCode 2.x с native worktree и профилями `standard`/`advanced`, Beads `bd` и embedded Dolt с историей `refs/dolt/data` в **том же Git remote**. `mis.yaml` не используется.

## Целевой Git-процесс (решение владельца)

1. `/mis-plan` формирует проверяемые Epic/Task и реальные зависимости из продуктовых требований (не переписывая их).
2. Для Task агент работает в отдельной native worktree, ограничивает затронутые contexts, реализует код и тесты, проводит независимый read-only AI-review.
3. Перед публикацией агент собирает интегрированный снимок: fetched `main` интегрируется в own-ветку обычным `git merge`, без force и разрушительных операций. На этом снимке выполняется **полный обязательный gate**: все unit, интеграционные, architecture, frontend тесты и E2E smoke desktop+mobile. Незапущенный или упавший набор не считается успешным.
4. Публикация — **только** через `mis-proj-op-publish-change`: non-force push в `main` с read-back проверкой remote ref/SHA. Это единственный санкционированный путь интеграции в `main`.
5. После push CI GitHub Actions прогоняет полный набор на `main` как пост-фактум подтверждение; сверяются remote ref/SHA, состояние Beads и документация. Публикация **не равна** продуктовой приёмке.
6. Владелец контролирует процесс выбором задач (`/mis-plan`, `/mis-run`, `/mis-bug`), пост-аудитом `main` (Git/Dolt/CI история) и вправе потребовать исправления или отката.

GitHub: branch protection, блокирующее прямые push в `main`, не включать — оно несовместимо с протоколом прямой публикации MIS. Рекомендуется включить только block force pushes. CI запускается по push в `main`.

## Решённая несовместимость с upstream MIS

Ранее здесь был зафиксирован preflight blocker: `/mis-run` считает публикацию Git-результата и закрытие Beads частью завершения Task, тогда как процесс проекта требовал обязательного ручного слияния, которого нет в контракте MIS.

**Разрешено владельцем 2026-11-05:** принят режим прямой публикации в `main` по контракту установленной ревизии (`e70a2423ceb18bf5e9db2964edae89af923570fd`; проверено по `mis-proj-op-publish-change`: direct push в primary ref, интеграция обычным `git merge` без force, recheck интегрированного снимка). `AGENTS.md` не переписывает установленный MIS; при смене ревизии через `/mis-update` заново проверить соответствие контракта публикации этим правилам и при расхождении остановиться и доложить владельцу.

## Содержание отчёта публикации

- Краткий пользовательский результат и способ проверить.
- Beads ID, затронутые Bounded Contexts, публичные контракты/миграции.
- Запущенные unit/integration/architecture/E2E проверки и непроверенное.
- Результат независимого AI-review, изменения docs/spec и скриншоты UI при наличии.
- Нет секретов, временных файлов, чужих непроверенных коммитов.

## Отсутствие самовольных полномочий

Разрешение на реализацию Task и commit в own-ветке — не разрешение на force push, переписывание опубликованной истории, удаление refs, изменение чужих данных или опасный deploy. Git и Beads/Dolt публикуются отдельно и проверяются отдельно; не скрывать частичный результат. Независимое AI-review MIS не заменяет пост-аудит владельца; подтверждённая публикация не равна продуктовой приёмке.
