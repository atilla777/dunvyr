# Frontend

## Стек и границы

React + TypeScript + Vite. Доменная логика авторизации, HP, очереди, расчёта бросков/голосования не исполняется доверенным образом на клиенте. UI может вычислять отображение доступных действий из серверного snapshot, но сервер повторно проверяет каждую команду.

Одна компонентная система, **несколько адаптивных layout** (mobile/tablet/desktop). Ключевые функции доступны на всех экранах; не строить два независимых frontend. Основные элементы: ChatPanel, SceneViewer/Thumbnail, LocationMap, CharacterPanel, Inventory, ActionPanel, VotingPanel, Journal.

## Scene и карта

Изображения сценария и координаты hotspot подготовлены заранее; React + SVG/CSS достаточно для MVP. **Phaser/PixiJS не обязательны** до появления реальных требований анимации, камеры и тактики. Hotspots доступны также через список объектов — игроку на телефоне не требуется попадать в мелкую область изображения. Масштабирование сохраняет видимые объекты, нельзя слепо обрезать сцену.

Карта строится из **отфильтрованного сервером** графа; клиент не должен получать скрытые комнаты/связи. Представления неизвестной комнаты (`???`) могут отображаться, только если игрокам известно о соответствующем выходе.

## Mobile

Чат основной; компактная закреплённая карточка сцены, кнопка карты, небольшие показатели персонажа; полноэкранные scene/map viewers и нижние панели для действий/инвентаря. Клавиатура не скрывает поле ввода, черновик сохраняется при переключении панели. Touch targets ориентир от 44×44 CSS px, управление без hover, контраст и focus-visible, клавиатурные альтернативы, читаемые состояния.

## Real-time UX

Все события имеют уникальные IDs; UI избегает дублирования при реконнекте и повторном snapshot. Отображать loading/error/stale/offline при ответе модели и синхронизации. Важные сообщения AI/NPC визуально выделены, но chronological chat единый. Закреплённый контекст считывает authoritative scene state. Не зависеть от stream текста для расчёта игровых исходов.

## TTS

По нажатию у реплик NPC/ведущего, индивидуально на устройстве, без автозапуска. Предпочтительно browser speechSynthesis для MVP, с graceful fallback (нет голоса — читаемый текст). Не хранить аудио, если не требуется функциональностью.

## Frontend quality

TypeScript strict (кроме оправданного временного исключения), ESLint, formatter, Vitest/Testing Library, Playwright mobile и desktop на критичных сценариях. UI не должен импортировать Python domain conventions как случайный JSON без согласованного API-контракта.
