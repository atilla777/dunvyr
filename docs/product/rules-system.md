# Dunvyr Rules

## Общий принцип

Универсальная **упрощённая система, вдохновлённая Fate Condensed**, не реализация Fate без изменений. Правила применяются к любым сеттингам; интерфейс и файлы конкретного мира задают навыки, оборудование и приключения. Использование лицензированных элементов Fate требует корректного указания авторства и соблюдения лицензии; см. [правило лицензий](../rules/knowledge-and-sdlc.md).

## Проверки

**Итог = Характеристика + Навык + 4dF + применимые модификаторы**.

`4dF` — четыре независимых кубика со значениями -1/0/+1. Сервер генерирует бросок и записывает достаточные данные для аудита результата. Навык имеет **одну фиксированную** характеристику, определённую сеттингом; AI не меняет привязку на лету. Конкретный навык и сложность задаёт сценарий/правила действия либо серверно проверенное предложение из разрешённых вариантов.

Общие сложности, границы характеристик/навыков, итог при равенстве и числовые модификаторы **ещё не согласованы**; нельзя интерпретировать иллюстративные значения прежних примеров как утверждённую формулу баланса. Для ограниченного небоевого среза «Последней смены» `noncombat-v1` принято: сложность 5, равенство означает успех, числовой модификатор 0 (Beads `dunvyr-lbp.6`); это не универсальное правило баланса.

## Здоровье и состояния

- У персонажа есть текущие и максимальные HP.
- При 0 HP персонаж теряет сознание; **окончательной смерти и исключения из игры в MVP нет**.
- Состояния определяют разрешённые действия и возможность разговора (например, unconscious блокирует оба; silence — соответствующую речь). Проверка — на сервере, не только скрытая кнопка в UI.
- Лечение, срок действия эффектов, пробуждение и исход поражения всей группы контролируются правилами и/или сценарием; точные значения открыты.

## Пошаговый бой

- `Combat` — вид испытания, со **смешанной фиксированной очередью игроков и противников**; обмен разрешён только между ещё не действовавшими игроками.
- Базовые действия: атаковать, защищаться, помочь, подготовиться, использовать допустимый предмет/способность мира или предложить нестандартный ход.
- **Один бросок атаки** по общей формуле проверяет попадание и величину повреждений.
- Урон = базовый урон оружия + **ограниченный бонус за степень успеха** при успешном попадании. Числовой cap не утверждён; не фиксировать выдуманные значения.
- **Защита фиксированная**, включает базовое значение, Ловкость, экипировку и временные бонусы. `Defend` расходует действие и временно повышает защиту.
- Противники выбирают разрешённое действие по **простым детерминированным правилам/приоритетам**; AI лишь narrates результат. Броски могут быть случайными; поведение противника не требует LLM.
- Победа не обязательно означает уничтожение: разрешены отступление, договор, обезвреживание и другие сценарно предусмотренные исходы.
- Нет тактической карты, позиций на клетках, дальностей и свободного передвижения во время боя в MVP.

## Для балансировки перед реализацией

Уточнить без отдельного долгого интервью по конкретным минимальным сценариям: пороги сложности, значение равенства, цена `Defend`/`Assist`/`Prepare`, формулы HP, уровни защиты, базовый урон, максимальный бонус урона, способ определения очереди, действия при неуспешных атаках и при полном поражении. Выбор не должен нарушать уже принятые принципы. Все числовые правила покрыть table-driven/property-based тестами.
