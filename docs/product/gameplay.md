# Игровой процесс

## Два режима

- **Свободное исследование:** обсуждения, вопросы, получение уже доступных сведений, выбор объектов, планирование. Нет обязательной очереди для обычного общения и изучения информации.
- **Разрешение испытания / бой:** значимое действие меняет сюжет, ресурсы или состояние мира; применяется фиксированная очередь участников. Испытание может завершиться за один ход либо длиться раундами.

Чат остаётся доступен всем способным говорить персонажам даже во время чужого хода. Ограничения состояний проверяет сервер.

## Значимые действия

Значимое действие — попытка разрешить сценарную ситуацию, изменить её результат или повлиять на устойчивое игровое состояние. Например: взломать дверь, убедить NPC открыть секрет, активировать устройство, атаковать. Обычный вопрос, разговор, чтение уже открытой информации, обсуждение плана или осмотр без новой проверки не требуют хода.

Свободная **бытовая подготовка** бесплатна, а формальное действие `Prepare`, дающее игровой бонус, расходует ход. `Assist` расходует ход ради бонуса союзнику; `Defend` — для временной защиты. Числа бонусов пока не утверждены.

## Очередь

- В активном испытании порядок участников фиксирован; каждый доступный участник имеет максимум **одно основное действие за раунд**.
- Активный игрок может **обменяться местами** в текущем раунде с ещё не действовавшим игроком; обмен не даёт добавочного действия. Противников нельзя менять местами с игроками.
- Нет накопления полноценных ходов; автоматический пропуск при невозможности действовать. При отключении игрока ход также автоматически пропускается без награды.
- Противники входят в общую фиксированную очередь боя. Конкретный расчёт начальной инициативы пока не утверждён.
- Взаимодействие с несколькими объектами в одной сцене не должно порождать несколько несогласованных одновременных очередей.

## Предложения действий

- AI может обнаружить в чате намерение значимого действия и предложить структуру (`ProposedAction`) без выполнения.
- Предложение адресовано конкретному игроку, может быть сохранено до его хода. Несколько предложений допускаются без механики сложного планирования.
- На собственном ходу игрок подтверждает, редактирует или отменяет предложение. Перед исполнением сервер повторно проверяет состояние персонажа, допустимость, доступность цели и обстоятельства.
- При недостаточной уверенности AI должен запросить уточнение. Отклонённое предложение не расходует ход.
- AI не вправе запускать расходующее ход действие в обход подтверждения.

## Перемещение группы

- В MVP **вся группа находится в одной локации** и перемещается вместе, даже если один участник отключился.
- Переход по известному маршруту выбирается **голосованием подключённых игроков**, по одному голосу на человека. Голосование не расходует ход.
- При абсолютном большинстве группа следует выбранному маршруту, если проход доступен; условия перехода и испытания по-прежнему проверяются.
- Если после голосования всех участников большинство не набрано, проводится повторный тур. Если и он не дал большинства, сервер случайно выбирает **из вариантов с максимальным числом голосов** и сохраняет результат. Вариант с нулём голосов не должен побеждать при наличии проголосовавших.
- Серверная логика голосования не зависит от AI. Детали тайм-аутов, воздержания и изменяющегося количества присутствующих — [открытые параметры](decisions-and-open-questions.md).

## Продолжение игры

Изменения состояния кампании сохраняются после каждого значимого события. Разговор, игровой журнал и контекст сцен доступны после новой встречи. Ошибки AI/TTS не должны повторно применять уже совершённую игровую команду.
