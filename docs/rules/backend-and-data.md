# Backend и хранение данных

## Стек

Python (версию выбрать/закрепить при bootstrap), FastAPI, SQLAlchemy 2.x, Alembic, SQLite. Pydantic — только API/внешние границы, не базовые доменные Entity. HTTP REST — настройка/чтение/действия; WebSocket — доставка real-time событий и соответствующих команд по выбранному контракту.

**Никаких SQLAlchemy-моделей как доменных объектов**, прямых DB-запросов из роутеров, repository, возвращающих ORM-объекты чужим контекстам, и долгих транзакций с LLM-вызовом.

## SQLite

Один серверный экземпляр и одна база. Включить foreign keys, проверять режим journaling (WAL как разумный кандидат) и тайм-ауты блокировок. Все изменения схемы через Alembic; не создавать схему `create_all` в рабочем приложении без миграций. DB-сессия/Unit of Work ограничены конкретной операцией. SQLite — не основание пропускать проверки конкурентных изменений: один активный writer всё равно требует аккуратной последовательности команд.

Гостевые сессии, кампании, персонажи, прогресс, chat events и журнальные записи сохраняются; не хранить каждый токен/полный сырой контекст LLM без необходимости. Секреты не сохранять в игре в открытом виде сверх необходимого.

## REST и WebSocket

- HTTP: идемпотентные или явно защищённые от повторов изменения (create campaign, join invitation, confirm action, vote, pause).
- WebSocket: real-time чат/игровые события/состояние присутствия; авторизация такая же строгая, как у HTTP, подтверждённые сообщения с server event ID/sequence.
- Reconnect: клиент сначала восстанавливает snapshot/историю событий и затем продолжает streaming без дублей и потерь по принятому протоколу.
- Несколько клиентов с одним и тем же токеном и повторные команды не должны создавать дубли или обходить право действия.
- Адаптеры должны уважать ownership контекстов при чтении и записи.

## Отказоустойчивость

Падение/таймаут модели не должен оставлять наполовину применённое действие; серверный результат сохраняется до генерации художественного описания. AI narrator можно повторить без повторной атаки/списания XP. Сохранение после значимого события, backup/restore SQLite в доверенной LAN-среде (минимум документированная резервная копия и проверка восстановления перед приёмкой).

## API contracts

Предпочитать стабильные схемы и понятные ошибки `forbidden`, `stale_state`, `invalid_action`, `not_found`, `conflict`, `retryable_provider_error`. Конкретные route/response shapes появляются в `docs/spec/` при реализации; не описывать неподтверждённые endpoints как готовые.
