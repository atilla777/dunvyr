# Атомарное подтверждение небоевого действия

Кандидат `dunvyr-lbp.6`, интеграция ожидается. Для одного подтверждения gameplay оркестрирует общую короткую SQLite-транзакцию под writer lock кампании; presence guard удерживается до commit в порядке DB → presence. Владелец каждого контекста реализует собственный порт участия без внутреннего commit/rollback: characters предоставляет проверенные входы, adventures применяет авторский outcome к своему прохождению, communication добавляет публичный факт в свой поток. Gameplay владеет предложением, очередью, аудитом и квитанцией. Composition root связывает адаптеры одной session; чужие внутренние репозитории и таблицы не становятся публичным контрактом.

Проверки и бросок, эффекты, терминальный переход, аудит, receipt и событие фиксируются вместе; ошибка откатывает всё. Только после commit выполняется best-effort уведомление; сеть и LLM внутри write-транзакции не вызываются. Повтор идентичной команды после проверки членства читает receipt, а не бросает заново. Это не универсальный механизм транзакций или outbox с гарантированной доставкой: восстановление опирается на сохранённые состояние и историю. Существующие use cases с собственным commit не используются как вложенные транзакционные участники.
