# Frontend-скелет: toolchain, минимальная страница, dev-сервер, проверки

Нормативные источники: [technology-and-infrastructure](../../rules/technology-and-infrastructure.md), [frontend](../../rules/frontend.md), [testing](../../rules/testing.md). Канонический fresh-clone flow — в корневом `README.md`.

## Toolchain и команды

- Версия Node — единственный источник истины: корневой `mise.toml` (`node = "24.22.2"`); `.nvmrc`/`engines` не используются (решение владельца 2026-11-05). Пакетный менеджер — npm в составе mise-Node.
- Все инструменты проверок (Vite, TypeScript, ESLint, Prettier, Vitest, Testing Library) — devDependencies `frontend/package.json`; точные версии — в `frontend/package-lock.json`. React/react-dom — единственные runtime-зависимости.
- Свежий клон: `mise install` → из `frontend/`: `npm ci` → проверки.
- Реальные команды проверок (из `frontend/`, все зелёные на снимке задачи):
  - `npm run lint` — ESLint 9 flat config (`typescript-eslint` recommended, `eslint-plugin-react-hooks`, `eslint-plugin-react-refresh`);
  - `npm run format:check` — Prettier 3 `--check` (lock/dist/coverage/node_modules исключены через `.prettierignore`);
  - `npm run typecheck` — `tsc --noEmit` (strict, `noUnusedLocals`/`noUnusedParameters`/`verbatimModuleSyntax`);
  - `npm run test` — `vitest run`;
  - `npm run build` — `tsc --noEmit && vite build` (production-сборка; `dist/` игнорируется Git).
- Публичный командный интерфейс — корневой `Makefile` (включая `make test-unit` с `npm run test`) — см. [tooling/commands](../tooling/commands.md); состав gate — в [testing](../../rules/testing.md).

## Минимальная страница

- Точка входа: `frontend/index.html` — `<div id="root">` + module-скрипт `/src/main.tsx`; `main.tsx` монтирует `App` в `StrictMode`, отсутствие `#root` — явная ошибка времени выполнения.
- `App` — срез гостевого входа (введён задачей dunvyr-u4k.1, контракт API — [backend/identity](../backend/identity.md)): при загрузке `GET /api/identity/me` → состояния `loading` («Проверяем сессию…») / `anonymous` (форма входа: label «Псевдоним», input, кнопка «Войти», ошибка с `role="alert"`) / `authenticated` («Вы вошли как …»). Заголовок `<h1>Dunvyr</h1>` присутствует во всех состояниях (контракт E2E smoke). С задачей dunvyr-u4k.2 после входа показывается срез организатора кампаний (контракт — [backend/campaigns](../backend/campaigns.md)): форма `CreateCampaignForm` («Название кампании» + «Создать кампанию») → экран `CampaignScreen` (ссылка-приглашение с копированием, панель участников). С задачей dunvyr-u4k.3 добавлены гостевой flow и восстановление: путь `/join/<secret>` разбирается минимально (`joinPath.ts`, без роутинговой библиотеки — Vite dev отдаёт SPA fallback) → `JoinScreen` (успех/отказ с понятной ошибкой); после create/join id последней кампании гостя хранится в localStorage (`lastCampaign.ts`) и при загрузке восстанавливается через `fetchCampaign` (F5 возвращает на экран кампании с актуальным составом; 403/404 очищают ключ); `CampaignScreen` роль-зависим (секция приглашения и кнопка «Отозвать ссылку» — только организатору). С задачей dunvyr-u4k.4 в `CampaignScreen` добавлен real-time чат (контракт — [backend/communication](../backend/communication.md)): `ChatPanel` размещён до секций приглашения/участников (mobile-приоритет), после подписки WS грузит историю через `fetchChatHistory`, live-события — через `chatSocket.ts` (same-origin WS), `chat.ts` дедуплицирует по `event_id` и сортирует по `sequence`, события `member_joined` live-добавляют участников в ростер экрана (счётчик мест обновляется без перезагрузки); с задачей dunvyr-u4k.5 `chatSocket.ts` получил bounded reconnect-протокол (5 попыток, backoff 500–8000 мс; после каждого open — resync через snapshot-курсор `after`, буферизация live-кадров до завершения snapshot; после исчерпания окна — честный offline) и статус `reconnecting` (loading/stale/offline-индикация `aria-live`) — детали протокола в [backend/communication](../backend/communication.md) §Фронтенд-срез и reconnect-протокол клиента. API-клиент — `src/api.ts` (относительный `/api`); продуктового роутинга (кроме `/join`) и стилевой темы нет. Стили — минимальный `index.css` (центрирование, типографика, светлая/тёмная схема через `prefers-color-scheme`, адаптив форм входа/кампании/присоединения, стили чата: свои/чужие сообщения, системные строки).

## Выбор приключения

Кандидат `dunvyr-kye.1` (интеграция ожидается): `AdventurePanel` на экране кампании загружает [состояние приключения](../backend/adventures.md). Пока выбор не сделан, все участники видят ожидание, а организатор — каталог, предупреждение об окончательности выбора и кнопки выбора. Пустой каталог показывается явно. После выбора участники видят название, описание и fingerprint версии; участник не видит кнопок выбора. Ошибки показываются с возможностью обновить состояние; при конфликте или устаревшем fingerprint каталог сбрасывается. Ожидающее состояние обновляется каждые 5 секунд в видимой вкладке и при возвращении к ней; запросы не заменяют более свежий результат. E2E проверяет выбор, обновление у участника без потери черновика чата, F5 и повтор после ошибки загрузки. Сцена, карта и создание персонажа в этом срезе отсутствуют.

## Dev-сервер и LAN

- `npm run dev` поднимает Vite dev-сервер на `localhost` по умолчанию.
- LAN-биндинг — явный opt-in: переменная окружения `DUNVYR_DEV_HOST` (LAN-IP или `0.0.0.0`) в `vite.config.ts` задаёт `server.host`; по умолчанию не `0.0.0.0` (правило LAN: открытие listener — только после осознанной настройки firewall и allowed origins). LAN-запуск обоих серверов одной командой — `make dev` (слушает `0.0.0.0` по умолчанию) — см. [tooling/commands](../tooling/commands.md).
- Прокси API (введён задачей dunvyr-u4k.1): `vite.config.ts` проксирует `/api` → `DUNVYR_BACKEND_ORIGIN` (default `http://127.0.0.1:8000`); с u4k.4 запись дополнена `ws: true` — тот же префикс проксирует и WebSocket-апгрейд чата (`/api/campaigns/{id}/chat`). Браузер всегда работает с API same-origin на адрес Vite-сервера — cookie сессии и Origin-проверки остаются корректными с любого LAN-хоста без перечисления origin'ов на frontend.
- Проверено на снимке задачи: dev-сервер отдаёт `GET /` → 200 (HTML с root-контейнером и module-скриптом) и `GET /src/main.tsx` → 200 (Vite-трансформированный модуль с React-mount).

## Тестовая архитектура

- Component-тесты через `@testing-library/react` в jsdom (матчеры — `@testing-library/jest-dom/vitest`, setup `src/test/setup.ts`): `src/App.test.tsx` (заголовок уровня 1 «Dunvyr», состояния экрана входа — форма при 401, «Вы вошли как …» после входа, отсутствие токена в `localStorage`/`document.cookie`; с u4k.2 — переход создание → экран кампании; с u4k.3 — восстановление последней кампании из localStorage и flow `/join/<secret>`), `src/LoginForm.test.tsx` (отправка псевдонима, отображение ошибки, блокировка кнопки при отправке; `fetch` замокан), `src/CreateCampaignForm.test.tsx` (валидация/отправка/блокировка), `src/CampaignScreen.test.tsx` (ссылка-приглашение, копирование в буфер, состав участников «организатор»/«вы», отсутствие секрета после повторного чтения; с u4k.3 — секция приглашения/кнопка отзыва только у организатора, состояние «Ссылка отозвана»; с u4k.4 — live-ростер из `member_joined` и mobile-порядок «чат раньше приглашения»), `src/JoinScreen.test.tsx` (успех/отказ с понятной ошибкой, маппинг `campaign_full`/`nickname_taken`) и `src/ChatPanel.test.tsx` (u4k.4 — отправка/поток/свои-чужие/дедуп по `event_id`; WS-транспорт замокан через инжектируемый `ChatTransportFactory`, т.к. jsdom не имеет `WebSocket`; u4k.5 — честные loading/stale/offline и восстановление пропущенного по курсору `after` без дублей) и `src/chatSocket.test.ts` (u4k.5 — транспорт: первый open с snapshot-барьером, backoff+буферизация до snapshot, повтор при сбое snapshot и offline после исчерпания окна, ошибка сокета как разрыв, отказ reconnect после явного close, отказ отправки при неоткрытом сокете; глобальный `WebSocket` замокан FakeWebSocket с fake timers) — итого 7 файлов / 52 теста на локальном снимке repair dunvyr-u4k.5 (интеграция ожидается).
- Конфигурация Vitest — в `vite.config.ts` (`environment: 'jsdom'`, `css: false` — стили в тестах не импортируются; `include: ['src/**/*.test.{ts,tsx}']`). Unit-тесты живут только в `src/`; Playwright-спеки живут в `e2e/` и в Vitest-прогон не попадают (введено задачей dunvyr-68c.4, подтверждено: `make test-unit` собирает 1 файл / 1 тест).
- Браузерные E2E — `@playwright/test`: конфиг `playwright.config.ts` и спеки `e2e/` покрываются `tsc --noEmit` (`tsconfig.json` include) и ESLint/Prettier; запуск — `make test-e2e-smoke` — см. [tooling/commands](../tooling/commands.md).

## Ограничения (ещё не существует)

CI (dunvyr-68c.5); E2E smoke и командный интерфейс — уже [tooling/commands.md](../tooling/commands.md). Чат/WS-срез существует (u4k.4, `ChatPanel` + `chatSocket.ts`/`chat.ts`, контракт — [backend/communication](../backend/communication.md)); reconnect-протокол клиента реализован (u4k.5, там же); сцены, панели действий, голосование — будущие вехи. Продуктовый роутинг за пределами минимального `/join/<secret>` (библиотека роутинга не вводилась) и продуктовая стилевая тема не существуют. Список «мои кампании» не существует — есть восстановление одной последней кампании (u4k.3, [backend/campaigns](../backend/campaigns.md)). Мобильный E2E чата существует с u4k.5 (сценарий двух гостей в обоих smoke-проектах, эмуляция устройства в Chromium — [tooling/commands](../tooling/commands.md)); поведение «клавиатура не скрывает ввод» обеспечено DOM-порядком и CSS, реальным мобильным E2E не проверяется.

Известные ограничения зависимостей (отложены по review задачи dunvyr-68c.2, L1/L2): `npm audit` на lock фиксирует 7 moderate уязвимостей (minimatch через `@typescript-eslint/typescript-estree`, только dev-toolchain, runtime-зависимости не затронуты); безопасного фикса без даунгрейда typescript-eslint нет — пере-аудит при следующем обновлении зависимостей. ESLint 9.x (EOL-линия) — осознанный выбор этой вехи; переход на ESLint 10.x возможен без даунгрейда typescript-eslint, кандидат на ближайшую подходящую задачу.
